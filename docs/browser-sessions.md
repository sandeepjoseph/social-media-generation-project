# Browser resource policy

Use one working tab per service/account needed for the current task. Reuse a
matching existing tab instead of opening another. Open distribution destinations
as they are needed, and close idle temporary tabs once their evidence is saved.
Keep the Director Studio tab and the current upload/review/generation tab when
they are needed; a completed old Flow project, duplicate Studio page, old review
chat, billing setup page or obsolete verification page does not need to remain
open merely because it was used earlier.

Before cleanup, inspect a fresh live tab inventory and identify uploads,
generation, processing, unsaved forms and unrelated owner work. Preserve any tab
whose closure could interrupt those activities. Multiple required account
sessions may need separate tabs; record why. If a temporary agent-created tab is
needed across turns, mark it as a handoff explicitly rather than accumulating
copies. Save required public URLs and production evidence in the private tracker
before closing completed tabs.

The browser control connection can fail independently of visible tabs in the
desktop app. If live inventory is unavailable, record cleanup as blocked and do
not claim tabs were closed, act on old tab IDs, restart the browser/app, or kill
processes. Resetting only the automation connection does not establish that a
visible browser is connected. Once reconnected, inspect current state before
resuming uncertain clicks or uploads to avoid duplicate publication.

Verify the remaining live inventory after cleanup and report the real count and
services retained. Reducing tabs can reduce resource use; it does not by itself
prove whole-system stability or authorize interrupting an active provider job.
