# Story metadata packaging and policy

`app.services.studio_growth.package_story(story_facts, platforms=DEFAULT_PLATFORMS, approval=None)` creates deterministic, local metadata drafts for YouTube long-form, YouTube Shorts, Facebook Reels, Instagram Reels, TikTok, Dailymotion, and Rumble. It does not upload or publish. The result includes each platform's title, description, a small set of tags derived from supplied story facts, keywords, verified chapters when supplied, thumbnail brief, title-promise review, captions path, and review queue. It also returns the master/captions SHA-256 checks, required approval state, and `package_sha256`.

Inputs use the orchestrator schema: `story_id`, `title`, `script_text`, `audience` (`age_min`, `age_max`, `language`, `made_for_kids`, `reviewed: true`), `fiction_taxonomy`, `moral_or_learning_intent`, structured `source_evidence`, `qa_report`, `captions` and `master` (`path`, `sha256`), `thumbnail_brief`, and optionally `synopsis`, `topics`, `keywords`, platform metadata overrides, chapters, and `ai_realistic_content`. The `qa_report` must pass and bind `story_id`, exact `script_sha256`, and verified `master_sha256`. The returned package contains the exact script SHA-256 so a script edit invalidates the package and its approval hash. Per-platform assets are supplied in `platform_assets[platform]` with `path`, `sha256`, `variant_reviewed: true`, and `audience_reviewed: true`; the service never treats the master alone as a verified Short/Reel variant. The title and supplied summaries are carried into drafts; an exact-package owner approval is required to bind those copy fields to human review. The packager does not invent plot events. Hashtags come only from concise, relevant supplied topics/taxonomy, are capped at five by this service, and never add generic trending tags.

## Evidence, review, and handoff

Each master, captions, and platform variant artifact must exist at the supplied path and match the supplied SHA-256 to be marked verified. Large media files are hashed in chunks. Chapters are emitted only when all timing entries have `timing_verified: true`, finite strictly increasing timestamps, and unique times; when a verified duration is available, times must be within it. YouTube long-form chapters are emitted only if the first is at 0:00, there are at least three, each segment is at least ten seconds, and a verified duration confirms the last segment's length. Otherwise, chapters are omitted and review is queued. `qa_report` must say `passed`, `pass`, or `approved` (or set `passed: true`) and bind the exact story ID, script hash, and master hash. Rights evidence needs structured entries for source/script/adaptation, visual assets, voice, and music/ambience. Use rights statuses `original`, `licensed`, `public_domain`, or `cleared`; use `not_used` only to state a category is absent. Missing categories or unknown status keeps the package blocked. This is a completeness check, not legal advice or a determination that a use is lawful.

`audience.made_for_kids` must be a boolean and must reflect the actual intended audience. Child-directed content is queued for an explicit platform-settings review. Never infer “made for kids” from animation style alone. Realistic synthetic or materially altered content stays queued until the platform disclosure decision has been reviewed. Platform tools still need their own final settings checked at handoff. For YouTube, realistic altered or generated scenes/audio can require disclosure; non-realistic animation does not necessarily require it. TikTok separately requires labels for realistic AI-generated imagery, audio, and video. See the primary platform policies below.

The approval argument is accepted for handoff only when `master_sha256` equals the verified master hash, `package_sha256` equals this package's canonical draft hash, and every required readiness check passes. The canonical hash excludes derived approval/readiness status fields to avoid a circular digest. `approval_record_matches_exact_package` distinguishes a matching recorded approval from `verified_for_exact_master_and_package`, which also requires all readiness checks. The separate `metadata_copy_review_status` says whether that exact title/description/hashtag package received owner review. A matching approval with failed QA, rights, captions, audience, disclosure, or platform-variant checks is reported as `recorded_but_blocked`; it cannot mark the package approved for handoff. `ready_for_publication` always remains false: this service prepares a handoff only. A separate publishing adapter must be built only for a platform's documented API and authorized account flow; no credentials are read here. Instagram account/API availability and settings need a human or app-side check. TikTok's documented inbox upload flow tells the user to continue editing and complete the post in TikTok. Rumble is treated as a manual upload target until an applicable official, authorized API flow is verified.

Never create fake engagement, force a child to like/comment/share/follow, promise reach or revenue, or upload duplicate backup copies. Keep experimentation to truthful title/thumbnail variants, one meaningful variable at a time. Record results only from observed analytics. The analytics CSV columns are exposed as `ANALYTICS_CSV_COLUMNS`: impressions, click-through rate, watch time, completions, production credits, accepted minutes, platform, variant, timestamp, source, and notes. Leave unavailable values blank; do not convert “unknown” to zero. Canadian monetization thresholds, eligibility, RPM, or revenue are not asserted by this package.

Music and third-party asset rights must be established per target. A platform's in-app music library may be licensed only for its own uses or non-commercial contexts; it does not automatically clear that music for cross-posting. Keep the source, license, permitted platforms/uses, and evidence in `source_evidence`, and hold packaging for review when the status is unknown.

## Platform documentation checked 2026-10-15

This service encodes only a subset of limits backed by official API references. Instagram, Facebook Reels, TikTok, and Rumble fields are drafts, not assertions that an account can publish through an API or that an app's current limits are captured. Re-check current UI/API constraints at handoff because platform capabilities change.

- **YouTube metadata:** Data API titles are limited to 100 characters, descriptions to 5,000 UTF-8 bytes, and total tags to 500 characters (spaces inside tag values count as quoted, and commas count). The service flags title/description/keyword overages instead of silently truncating. [YouTube Data API video resource](https://developers.google.com/youtube/v3/docs/videos)
- **YouTube AI disclosure:** Realistic generated or altered content that depicts events, places, or people as though real may need the creator's disclosure in Studio; fantastical/non-realistic animation is given as an example that does not require disclosure. [YouTube altered or synthetic content disclosure](https://support.google.com/youtube/answer/14328491?hl=en)
- **YouTube children and quality:** Audience selection must fit the actual audience. YouTube's kids/family guidance highlights coherent stories and clear takeaways, and warns against misleading, keyword-stuffed metadata and low-quality mass-produced content. [Kids and family best practices](https://support.google.com/youtube/answer/10774223?hl=en), [child safety policy](https://support.google.com/youtube/answer/2801999?hl=en)
- **YouTube chapters:** When creator-supplied chapters are used, the first timestamp must be `00:00`, there must be at least three timestamps in ascending order, and each chapter must be at least 10 seconds long. The packager requires verified duration to check the last chapter boundary. [Video chapters](https://support.google.com/youtube/answer/9884579?hl=en)
- **YouTube originality and engagement:** Monetization policies require original/authentic material rather than repetitive mass-produced content; fake engagement is covered by YouTube's community policies. Nothing here predicts monetization or views. [YouTube channel monetization policies](https://support.google.com/youtube/answer/1311392?hl=en), [Community Guidelines](https://support.google.com/youtube/answer/9288567?hl=en)
- **Facebook Reels:** Meta's current help page says Reels can be uploaded from a computer, gives a description/hashtag field, and requires the creator to select the audience before publishing. Another Help Center page notes that all videos are moving into Reels and may be any length or orientation as that change rolls out; this is why the package does not hard-code a length/aspect limit. [Create a Facebook Reel](https://www.facebook.com/help/www/2862139500770200), [Explore Facebook Reels](https://www.facebook.com/help/262748009210134/)
- **Instagram Reels and music:** Meta's developer-posted collection documents Reels publishing through a media container then a publish step and has video specs, but app/API eligibility and actual account access still need verification. Captions are left conservative and hashtags limited by this service's own choice rather than asserting a universally current platform cap. Meta says its licensed Instagram music library is intended for personal, non-commercial use, with Sound Collection available for commercial use; verify terms for each use. [Meta Instagram API collection](https://www.postman.com/meta/workspace/instagram/documentation/23987686-9386f468-7714-490f-9bfc-9442db5c8f00), [Instagram music library](https://www.facebook.com/help/instagram/402084904469945)
- **TikTok:** The Content Posting API's inbox flow is an upload, after which the user is told to continue in TikTok to edit and complete the post. TikTok requires labels on realistic AI-generated content; its commercial music guidance recommends the Commercial Music Library for posts promoting a brand/product/service. [Content Posting API upload](https://developers.tiktok.com/docs/en/content-posting-api-reference-upload-video), [AI-generated content rules](https://support.tiktok.com/en/using-tiktok/creating-videos/ai-generated-content), [commercial music use](https://support.tiktok.com/en/business-and-creator/creator-and-business-accounts/commercial-use-of-music-on-tiktok?lang=en)
- **Dailymotion:** Its current v2 upload docs require title, category, visibility, and an explicit `is_for_kids` value; the API reference documents a 1–255 character title and description up to 3,000 characters. The packaging module flags those text limits. [Upload videos](https://developers.dailymotion.com/docs/upload-videos), [update video reference](https://developers.dailymotion.com/reference/update-video)
- **Rumble:** Rumble's official help material documents manual subtitle upload formats, but the cited public materials do not establish a currently supported general video publishing API or metadata limits. The package therefore prepares human-editable fields and makes no API-publishing claim. [Rumble subtitle help](https://rumble.support/help/closed-captioning-subtitles-accepted-formats)

## Analytics CSV

Write a header using `ANALYTICS_CSV_COLUMNS`. Keep missing metrics empty. A row should describe an observed post/variant and include the source and notes needed to reproduce the measurement; do not fill unobserved numbers with zero or infer a performance result from a platform recommendation.
